### Millard · 2026-09-02 17:03

On Win 11, what is the max # chars allowed for a full pathfile name?

### Claude · 2026-09-02 17:03

260 characters by default (MAX\_PATH, 259 usable), or about 32,767 if long path support is enabled in the registry and the app supports it.

### Millard · 2026-09-02 17:04

I'm getting lots of copy errors because the resulting file names would be too long.

### Claude · 2026-09-02 17:04

Enable long paths, then copy with robocopy (File Explorer still chokes on them even after the switch).

Registry: set `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled` (DWORD) to 1, reboot.

Or gpedit: Computer Configuration → Administrative Templates → System → Filesystem → "Enable Win32 long paths" → Enabled.

Copy command: `robocopy "C:\source" "D:\dest" /E /COPY:DAT /R:1 /W:1`

### Millard · 2026-09-02 17:05

Will enabling long paths have any collateral effects?

### Claude · 2026-09-02 17:05

Minor. Known effects:

* Older apps built without the `longPathAware` manifest flag still fail at 260 — the setting only helps apps that opt in. Explorer, cmd, many installers, and some third-party tools stay limited.
* Files you create beyond 260 become unreachable/undeletable by those apps, and by any tool you later run on a machine where the setting is off.
* Backup, sync, and antivirus software that hasn't been updated can silently skip or error on the long paths.
* Zip/archive tools and cloud sync clients (OneDrive, Dropbox) have their own separate limits that don't change.

No performance or stability cost. It's a per-machine setting, not per-user, and reversible.
