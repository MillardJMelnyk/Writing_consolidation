Position Size = (Account Balance × 0.01) ÷ Stop Loss in pips ÷ Pip Value

### Claude · 2025-11-22 13:19

The formula solves for: "How many units can I trade so that if my stop loss triggers, I lose exactly 1% of my account?"

**The algebra:**

Risk Amount = Position Size × Stop Loss (pips) × Pip Value

Rearranged:

Position Size = Risk Amount ÷ (Stop Loss × Pip Value)

Which is equivalent to the chained division in the formula.

**Example:**

* Account: $10,000
* Risk: 1% = $100
* Stop Loss: 50 pips
* Pip Value: $0.10 per pip per micro lot

Position Size = $100 ÷ 50 ÷ $0.10 = 20 micro lots

**Verification:** 20 micro lots × 50 pips × $0.10 = $100 loss if stopped out. Correct.

**The reasoning:** Your stop distance and pip value together determine how much each unit of position costs you if wrong. Dividing your acceptable dollar risk by that cost-per-unit gives you the maximum position size that caps your loss at exactly 1%.

### Millard · 2025-11-22 13:20

define pip value

### Claude · 2025-11-22 13:20

Pip value is the monetary gain or loss your position incurs per one-pip price movement.

**Determinants:**

1. **Lot size** — Larger position = higher pip value
2. **Quote currency** — The second currency in the pair (e.g., USD in EUR/USD)
3. **Account currency** — If your account isn't denominated in the quote currency, exchange rate conversion applies

**Standard pip values (when USD is quote currency):**

* 1 standard lot (100,000 units): $10/pip
* 1 mini lot (10,000 units): $1/pip
* 1 micro lot (1,000 units): $0.10/pip

**When USD is base currency (e.g., USD/JPY):**

Pip value = (0.0001 ÷ exchange rate) × lot size

Requires conversion because the quote currency (JPY) isn't your account currency (USD).

**Why it matters for the formula:**

Stop Loss (pips) × Pip Value = dollar risk per unit of position. You need this to calculate how many units you can hold without exceeding your 1% risk cap.

### Millard · 2025-11-22 13:22

Give me a different way of setting position size that isn't a function of percentage of account balance

### Claude · 2025-11-22 13:22

**Fixed Dollar Amount**

Risk a flat sum per trade (e.g., $100) regardless of account size. Position size = $100 ÷ (Stop Loss × Pip Value). Simple, but doesn't scale with growth or drawdown.

**Fixed Lot Size**

Trade the same lot size every time. Your risk percentage fluctuates based on stop distance. Ignores account changes entirely.

**Volatility-Based (ATR)**

Position Size = Risk Amount ÷ (ATR × Pip Value)

Uses Average True Range instead of arbitrary stop distance. Automatically adjusts for market conditions—tighter positions in volatile markets, larger in calm ones.

**Kelly Criterion**

Kelly % = Win Rate − [(1 − Win Rate) ÷ Reward-to-Risk Ratio]

Calculates mathematically optimal bet size based on your historical edge. Requires accurate win rate and RR data. Most traders use fractional Kelly (e.g., half-Kelly) because full Kelly is aggressive.

**Fixed Ratio (Ryan Jones)**

Increase lot size only after accumulating a fixed profit amount (the "delta"). Example: Start at 1 lot, add 1 lot after every $5,000 profit. Slower scaling than percentage-based, smoother equity curve.

**Conviction-Based**

Assign position sizes by setup quality: A-grade setups get full size, B-grade gets half, C-grade gets quarter or skip. Subjective, but forces selectivity.

**USD as quote currency (EUR/USD, GBP/USD, AUD/USD):**

Yes. You must convert the quote currency to USD at the prevailing rate. Fluctuates continuously.

For non-USD-quote pairs, your position size calculation is only accurate at the moment you calculate it. By the time your stop triggers, pip value may have shifted slightly. Usually negligible intraday, but can matter on longer holds or during volatile conditions.

### Claude · 2025-11-22 14:02

Options for determining the 95th percentile adverse level:

**1. Maximum Adverse Excursion (MAE) on candles**

Over N candles, measure the maximum move against your direction from open. For longs: Open − Low. For shorts: High − Open. Take the 95th percentile of that distribution.

Requires: Lookback period (e.g., 500 candles), timeframe selection.

**2. ATR multiple**

Calculate ATR over N periods. Multiply by a factor calibrated to your historical data. Problem: ATR measures average volatility, not tail. The multiplier is a guess unless you backtest to find what multiple captures 95%.

**3. Rolling high-low range percentile**

Measure the full range (High − Low) of each candle over N periods. 95th percentile gives you the range that's only exceeded 5% of the time. Use that as your adverse buffer from entry.

Simpler than MAE but less precise—it includes favorable movement.

**4. Close-to-close returns distribution**

Calculate percentage returns over N periods. Find the 95th percentile adverse return. Apply that percentage to current price.

Better for swing trades where you're holding across closes.

### Claude · 2025-11-22 14:28

**Nearest-neighbor pattern matching:**

Take the current market state, encode it as a set of values (a vector). Compare that vector to historical vectors. The historical instances most similar to the current one are its "nearest neighbors." Use outcomes from those neighbors to predict what happens next.

Example: Current state = [Hull1 > Hull2, Hull1 rising, Stoch signal > Stoch main, EMA below both Hulls]. Search history for times when the same configuration occurred. Those are the matches.

**ZigZag as the framing structure:**

The ZigZag defines *what* gets compared and *over what span*.

Each ZZ pivot pair (high-low or low-high) creates a segment. You said X pivot pairs defines the pattern window. So if X = 3, you're looking at the indicator states across the last 3 ZZ swings.

ZigZag provides:

* Temporal boundaries (where the pattern starts/ends)
* Price boundaries (the range of the pattern)
* Normalization anchor (current pattern's spread vs historical pattern's spread)

Without ZigZag, you'd be comparing arbitrary fixed-length windows. With it, you're comparing structurally equivalent market movements—swing to swing.

### Claude · 2025-11-22 14:38

Correct. Options:

**Binary feature matching** — Encode everything as discrete states (above/below, rising/falling). Threshold = percentage of features that must match exactly. Simple, but loses granularity.

**Distance-based (Euclidean, Manhattan)** — Encode as continuous normalized values. Threshold = maximum distance. Captures degree of similarity, but requires sensible normalization across different feature types.

**Cosine similarity** — Compares vector angles, ignores magnitude. Threshold = minimum similarity score (0 to 1). Good when relative proportions matter more than absolute values.

**Dynamic Time Warping (DTW)** — Handles patterns that are similar in shape but stretched/compressed in time. Threshold = maximum warping distance. More computationally expensive.

**Weighted hybrid** — Assign importance weights to features. Some features must match exactly (e.g., Hull trend direction), others allow tolerance (e.g., pivot coordinates within X%). Threshold = minimum weighted score.

Your pattern has both categorical data (above/below, rising/falling) and continuous data (pivot X/Y coordinates). Suggests either weighted hybrid or a two-stage filter: hard requirements on categorical features, then distance-based ranking on continuous features.
