### Claude · 2026-08-11 20:29

Yes — you can re-add the firewall permission through Windows Settings.

**Fix via Windows Defender Firewall:**  
1. Open Start menu, search "Allow an app through Windows Firewall" and open it.  
2. Click "Change settings" (needs admin rights).  
3. Look for the Shogun 2 entry (or "Total War: SHOGUN 2") in the list.  
4. Check both "Private" and "Public" boxes next to it.  
5. Click OK.

**If it's not in the list at all:**  
1. Click "Allow another app..." (or "Allow another app" button).  
2. Browse to the game's .exe (usually something like `...\Steam\steamapps\common\Total War SHOGUN 2\Shogun2.exe`).  
3. Add it, then check Private and Public, then OK.

That said — the game shutting down right after launch is more commonly caused by something else (Steam not fully connecting, missing DirectX/VC++ redistributables, or the game needing to phone home to Steam even in "offline-ish" single player). If re-allowing it through the firewall doesn't fix the closing issue, that's the next thing to check.

### Claude · 2026-08-11 20:32

Let's narrow it down. A few quick checks:

**1. Does it crash instantly, or after the splash screen/menu loads?**  
- Instant = usually launcher/redistributable issue  
- After menu = usually graphics/mod/save issue

**2. Check Steam is actually running**  
Total War: Shogun 2 needs Steam running in the background even for single-player. Make sure Steam is open and you're logged in (offline mode is fine, but Steam.exe needs to be running) before launching the game.

**3. Verify game files**  
In Steam: Library → right-click Shogun 2 → Properties → Installed Files → "Verify integrity of game files." This catches corrupted downloads, a common cause of crash-on-launch.

**4. Install/repair the redistributables**  
Shogun 2 needs DirectX and Visual C++ redistributables that don't always install cleanly. In the game's install folder look for a folder like `_CommonRedist` and run the DirectX and VC++ installers inside it manually.

**5. Check the crash logs**  
Look in `Documents\My Games\Total War Shogun 2\` for a log file — it often names the exact missing DLL or module causing the crash.

**6. Compatibility mode**  
Right-click the exe → Properties → Compatibility tab → try running as Administrator, and if you're on Windows 10/11, try Windows 7 or 8 compatibility mode.

Which step matches what you're seeing — instant crash before any window appears, or does a window/splash flash and then close?

### Claude · 2026-08-11 20:33

This is a widely reported crash pattern for this game — it's during the load-into-3D-engine transition, not your firewall setting. Common causes and fixes, roughly in order of success rate:

**1. Delete the user config folder and let it regenerate**  
Go to `C:\Users\<YourName>\AppData\Roaming\The Creative Assembly\Shogun2` and delete (or rename) that folder. A corrupted preferences file in that folder is a known cause, and users have been told to delete it and then verify the game cache so it regenerates.

**2. Verify game files again after that**  
Steam → Library → right-click Shogun 2 → Properties → Installed Files → Verify integrity.

**3. Skip the Total War launcher, run the game exe directly**  
One user found the crash was tied to the Total War launcher itself, and launching `Shogun2.exe` directly from the game folder worked. Try: Steam → right-click Shogun 2 → Manage → Browse local files → run `Shogun2.exe` (not the launcher) directly.

**4. Force DirectX 9 instead of 11**  
Some users report DX11 is what triggers the crash on the loading transition, while choosing DirectX 9 lets the game work correctly, whereas DirectX 11 causes the crash. In the launcher options (or via a launch option if you bypass the launcher), select DirectX 9.

**5. Update/reinstall GPU drivers**  
Old or mismatched graphics drivers are a frequent culprit for this exact "loads splash → cursor changes → crash" symptom.

**6. Antivirus/security suite interference**  
Oddly, several users report third-party antivirus (not just Windows Firewall) interfering with this exact crash — worth temporarily disabling yours to test.

Try #1 and #3 first — those have the best track record for this specific symptom. Let me know what happens.
